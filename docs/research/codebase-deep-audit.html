Bugs, Concurrency & Data Integrity Risks

8 Bugs
Moving or Renaming a Note Across Folders Corrupts It Permanently
Renaming a note updates the database, but forgets to update the header inside the actual file.
Critical Data Corruption server/src/notes/store.ts:331
›
💡 In Plain English: Imagine you put a letter inside an envelope addressed to "Archive", but the letterhead inside still says "Active Project". The strict post office inspection rule says: "The envelope and the letterhead must match 100%, or this document is rejected." Because the letterhead wasn't updated, the system marks the note as corrupted and refuses to let you or any AI agent open or edit it ever again!
Where It Happens: server/src/notes/store.ts in renameNote()
The Technical Root Cause: The database row type is updated, and the file is moved on disk. But the YAML frontmatter text inside the Markdown file is not rewritten. Next time the note is loaded, validateNote() throws OkfValidationError.
How to Fix: Inside renameNote, read the file, update frontmatter.type = toResolved.type, and re-serialize the file to disk atomically.
Live Collaboration Silently Overwrites External Edits and Reverts
If you have a note open in your browser, external REST edits or revision reverts get erased on your next keystroke.
Data Loss / Concurrency server/src/sync/collab-server.ts:140
›
💡 In Plain English: You and a colleague are looking at a shared whiteboard. Behind the scenes, someone in the back office updates the master document. But your whiteboard didn't get the memo! The moment you write a single period or close your browser, your whiteboard copies its older version over the master document, completely wiping out what the back office just did.
Where It Happens: server/src/notes/routes.ts:100 (REST update) and server/src/notes/store.ts:510 (revertNote)
The Technical Root Cause: MCP tools were given writeThroughCollab(), but standard REST updates and revision reverts bypass it and call updateNote() directly. The in-memory Yjs document in Hocuspocus never receives the change, and its debounced store later clobbers the disk.
How to Fix: Route all note updates (REST PUT and revertNote) through writeThroughCollab().
Database & Hard Drive Can Get Permanently Out of Sync on Rename Failures
If moving a file fails on the hard drive, the database still remembers the new name.
State Desynchronization server/src/notes/store.ts:349
›
💡 In Plain English: You change the address in the library catalog first. Then you go to move the book to the new shelf, but your cart breaks and the book stays where it was. Now the catalog says the book is on Shelf B, but it's really on Shelf A. Anyone looking for it will never find it!
The Technical Root Cause: db.update() runs without a rollback mechanism before fs.rename() completes. If disk rename throws, DB has the new path, disk has the old path.
Renaming a Note Breaks Every Wikilink Pointing to It
When you rename a note, other notes that link to it are not updated, creating dead links.
Broken Links server/src/notes/store.ts:331
›
💡 In Plain English: If you change a street's name from "Main Street" to "Broadway", but you don't update any of the road signs or maps in town, everyone trying to follow directions to "Main Street" gets lost.
How to Fix: When renaming a note, find all notes in the vault containing [[old-path]] and replace them with [[new-path]].
Deactivated Users Are Bricked and Cannot Be Reactivated
An admin can deactivate a user, but the software has no button or API to ever turn them back on.
Admin Lockout server/src/auth/admin-routes.ts:118
›
💡 In Plain English: The admin dashboard has an "Off" switch for employees, but no "On" switch! If an admin temporarily deactivates someone (e.g. during a leave of absence), they can never reactivate that account.
How to Fix: Add a POST /users/:id/reactivate route that flips status: 'active'.
Brute-Force Login Protection Resets on Every Server Restart
Failed password attempt counts are kept in temporary computer memory instead of the database.
Security / Rate Limiting server/src/auth/lockout.ts:1
›
💡 In Plain English: The security guard counts failed passcode attempts on a dry-erase board. Every time the server restarts or if you run multiple servers, the board is wiped clean, giving attackers fresh attempts to guess passwords.
Old Login Sessions and Password Reset Tokens Accumulate Forever
Expired login sessions from months ago are never deleted from the database.
Resource Leak server/src/auth/sessions.ts
›
💡 In Plain English: Imagine a hotel that never throws away expired room keycard records. After a year, the filing cabinet is overflowing with useless junk cards.
Search Returns 0 Results If Filtered Notes Fall Outside Top 30
The search engine only grabs 30 candidates before filtering, missing relevant notes deeper in the list.
Search Starvation server/src/search/search.ts:154
›
💡 In Plain English: You ask for "red apples". The store clerk only looks at the top 30 fruits on the table (which happen to be 30 oranges) and tells you "we don't have any red apples", even though a basket full of red apples was sitting on shelf 31 right behind the oranges!

Missing Features (Standard Industry Capabilities)

11 Features
No Image or File Attachment Support (Notes are Text-Only)
Users cannot drag, paste, or upload screenshots, diagrams, PDFs, or files into their notes.
Major Limitation
›
💡 In Plain English: Every modern note app (Notion, Obsidian, Apple Notes, Slack) lets you copy a screenshot and paste it directly into your notes. In Chapters today, notes are strictly plain text — there is no place to store or display pictures.
No Math (KaTeX) or Flowchart (Mermaid) Rendering
Scientific formulas and visual architecture diagrams are rendered as ugly raw text blocks.
Markdown Engine
›
💡 In Plain English: Engineers and researchers love writing formulas and Mermaid diagrams in markdown. Chapters doesn't render them into pretty visual diagrams; it just shows the raw code.
No Live Multi-User Cursors or Presence Badges
You cannot see where your teammates' cursors are, or who is currently looking at the note.
Collaboration UI
›
💡 In Plain English: In Google Docs or Figma, you see little colored flags with your teammates' names floating around so you don't type over each other. In Chapters, edits sync behind the scenes, but the people editing are invisible "ghosts".
No One-Click Importer from Obsidian or Notion
You can only import from Chapters' own internal zip format, making migration from other apps painful.
Onboarding Friction
›
💡 In Plain English: If a prospective user already has 500 notes in Obsidian or Notion and wants to switch to Chapters, they have to write custom scripts to convert their files because Chapters has no "Import from Obsidian/Notion" button.
No Git Commit History, Diffs, or Blame Annotations
Connected code repositories can only be browsed as static files; git history is not stored.
Code Intelligence
›
💡 In Plain English: You can see the code, but you can't see who wrote a line, when it was changed, or what changed between two versions.
Code Repositories Are Strictly Read-Only (Cannot Edit or Commit)
You cannot fix typos or edit files in connected repositories from the Chapters UI.
Developer Workflow
›
💡 In Plain English: The code viewer is a glass display case: you can look at the code, but you cannot touch or update it.
Code Symbol Extraction Missing for Rust, Java, C++, C#, and Ruby
Symbol extraction only supports TypeScript, JavaScript, Python, and Go.
Language Coverage
›
💡 In Plain English: If your team writes in Rust, Java, C++, or C#, the AI graph cannot automatically map out your functions and classes like it does for TypeScript or Python.
No Visual Custom Metadata Editor or Notion-Style Database Views
Custom note properties are displayed as read-only text, with no table or board views.
Knowledge Management
›
💡 In Plain English: In Notion or Obsidian, you can turn notes with tags/dates into a Kanban board or a spreadsheet table. In Chapters, notes can only be viewed one-by-one.
Cannot Isolate Local Graph Neighborhoods or Export Graph Images
The knowledge graph cannot focus on 1-hop connections or export to PNG/SVG/JSON.
Graph Controls
›
💡 In Plain English: You cannot say: "Show me only the notes connected to this specific project." It's either the whole universe or community clusters. Nor can you download a picture of your graph to put in a presentation.
No User Names or Avatars (Users Are Just Raw Email Addresses)
The database has no name or avatar columns; everyone appears as their full email.
User Profile
›
💡 In Plain English: Instead of seeing "Taha" with a nice profile picture, every revision, share, and notification displays 85902429+Taha-Mahmoodi@users.noreply.github.com.
MCP AI Surface Lacks Resources and Prompts (Tools Only)
AI clients like Cursor or Claude Desktop cannot attach notes as live URI resources.
AI Protocol
›
💡 In Plain English: The Model Context Protocol (MCP) lets AI agents browse knowledge bases. Chapters provides 52 tool actions, but does not provide standard "Resource Links" or pre-canned "Prompts", limiting compatibility with tools like Cursor.

Missing Functionalities & Incomplete User Journeys

9 Flows
Revision History Has No Diff View (You Restore Blindly)
You can see that a revision occurred at 2:15 PM, but cannot see what changed before clicking Revert.
Missing UX Flow
›
💡 In Plain English: It's like having a "time machine" button, but with your eyes closed. You know it will take you back to Tuesday, but you have no idea what your document looked like on Tuesday until you actually press the button.
Clicking a Simple Wikilink Without a Type Fails to Create It
Clicking [[meeting-notes]] fails because Chapters requires a type prefix like [[project/notes]].
Knowledge Creation
›
💡 In Plain English: In Obsidian, typing [[my-idea]] and clicking it instantly creates that note. In Chapters, if you forget to prefix it with a type folder (like [[topic/my-idea]]), the app fails to create the note and shows an error.
No Incoming Backlinks Panel in the Note Inspector
When reading a note, you cannot see which other notes link to it.
Second Brain Core
›
💡 In Plain English: The core premise of a "second brain" is two-way links: when you're looking at a client note, you should see every meeting where that client was mentioned. Chapters has no backlinks list in the side panel!
Search Results Do Not Highlight or Jump to the Word in Editor
Clicking a search result opens the note at the top, without scrolling to the matched phrase.
Search Usability
›
💡 In Plain English: If you search for a specific sentence inside a 20-page document, clicking the search result just drops you at page 1. You have to manually search all over again to find where that sentence was.
No "Mark All as Read" Button for Notifications
If you have 50 notifications, you must click every single one individually to clear the badge.
Notification Fatigue
›
💡 In Plain English: Imagine opening your email and having to click 50 separate emails one by one just to make the "50 unread" badge go away!
Cannot Invite Teammates by Email (They Must Already Have an Account)
Adding a team member returns "404 user not found" if they haven't signed up yet.
Team Growth
›
💡 In Plain English: Usually, you invite a coworker by typing their email and they receive an invitation link. In Chapters, you cannot invite someone who hasn't already registered and been approved first.
No Bulk File Actions in Vault Tree (One-By-One Only)
Users cannot select multiple notes to move, tag, export, or delete them in batches.
File Management
›
💡 In Plain English: If you want to move 20 notes into an "Archive" folder, you have to click, rename, and move all 20 notes one by one.
Mobile UI Breakage: Sidebars Overlap on Small Screens
The floating full-screen shell has no mobile drawer mode; side panels swallow the editor.
Responsive Design
›
💡 In Plain English: On an iPhone or mobile screen, the left menu and the right inspector panel are so wide that they collide and completely cover your text editor.
Export Formats Restricted to Zip & Markdown (No PDF or Print)
Users cannot export notes as clean PDFs, HTML documents, or print-friendly pages.
Export Flexibility
›
💡 In Plain English: If you need to send a formatted proposal or meeting note to an executive or client as a PDF, Chapters cannot do it. You have to copy-paste it into Word or Google Docs first.
