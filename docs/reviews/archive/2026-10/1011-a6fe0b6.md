## Minor
- **The share-change assertion in `server/test/cache-key.test.ts:140-146` proves nothing.** `k0` is read before `createActiveUser()`, and that user insert already moves the permission epoch. With the `INSERT INTO vault_shares` line removed, the test still passed. Reading `k0` after `createActiveUser()` fixes it. The behaviour itself is properly covered by `cache-epochs.test.ts:275`.
- **The bump marker scan is quadratic in very large transactions.** `index_epoch_bump` scans `elara.index_epochs_bumped` with `position()` on every queued row event, so a single transaction that touches many scopes (e.g. a restore of a large multi-vault archive) costs O(events × scopes). Negligible at normal sizes; I did not measure it.
