## Findings (blocking)
1. **`checks` is red because of this PR** — `server/src/mcp/server.ts:1445`, `:2268`.
   - Adding `session_id` changes the unknown-argument suggestion list. `test/mcp-errors.test.ts:171` still expects `['vaultId','path','targets','outline','if_rev','budget_tokens','cursor']`.
   - It fails in CI (run 40258064690) and locally on the merge.
   - Fix: add `'session_id'` after `'if_rev'` in that expectation. The PR's list of local results skipped this file.
2. **A reference on page 1 is sent again in full by later cursor pages** — `server/src/mcp/response.ts:355`, `:616-628`.
   - **Cause:** `compose` shows a `ref` section whatever the page's stop point is, and counts it as "shown whole". The cursor does not record that the section was answered by reference, and cursor pages never refer, so the continuation sends it again.
   - **Repro 1 (targets):** session read `{lines:'70-72'}`, then `targets [{lines:'1-60'},{lines:'70-72'}]` with `budget_tokens:256`.
     - Page 1 gives part 2 as `same_as` and reports `shown.targets: 9`.
     - Pages 2–10 list `{"next":"70-72"}` for that part.
     - Page 11 sends lines 70-72 in full.
   - **Repro 2 (`read_file` whole):** the content changed but the symbols did not.
     - Page 1 sends `symbols: {same_as}` while the content is cut at L34.
     - Pages 4–6 then send all 40 symbols (12 + 19 + 9).
   - **Impact:** extra tokens on any paged read, and a `truncated` block that contradicts the later pages.
   - **Fix:** either carry the indices of sections answered by reference in the cursor and treat them as `start: -1` in `slots()`, or only refer to sections before the page's stop section.
3. **The token delta was never measured on the agent harness.**
   - The bench is identical on every metric because the premise policy (`benchmarks/lib/policies.ts`) never re-reads within a question and sends no `session_id`, so it cannot exercise the feature. The PR's "Not covered" says the same for the agent trial.
   - The only saving shown (−19%) comes from a 12-call script the author chose inside a unit test.
   - For a token feature, this needs an `agent-trial` run on the same base (dev against the branch, with `session_id` exposed or taught), reporting tokens per task.
4. **Not mergeable as it stands.**
   - The PR is `CONFLICTING` with `dev`: `_journal.json` needs both 0052 and 0056.
   - `lab` is red on `monitoring-alerts`: 3 regressions where the sync status was `idle` instead of `error`. This looks unrelated (it passed in runs 40263598650 and 40278461960), but the gate needs a green re-run on a current merge ref.
   - Landing order follows `when`: 0056 must land after #1023 (0053) and the 0054 reservation (#469), or those migrations will be skipped on any instance that already applied 0056.
