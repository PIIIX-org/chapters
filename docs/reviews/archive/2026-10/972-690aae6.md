## Minor
- **The budget count and the benchmark count differ by one character per block.** `charsOf` adds up the block lengths, but the benchmark and lab `text` join the blocks with `\n`, as `benchmarks/README.md` now says explicitly. So a full page measures `budget_tokens × 4 + 1` the way the benchmark counts it. I measured LONG and README at budget 600 with a largest page of 2,401 characters, which is 601 tokens. The new test misses this because its `size()` joins with `''`. Fix: count `blocks.length` separator characters in `charsOf`, or state the no-separator rule in the README and the instructions ("characters / 4 … fit it").
- **A missing body block is silently treated as empty.** `answerJson` turns a missing `content[1]` into `''`, and `tool-answer.test.ts` asserts this. `toolText` drops the key instead. A server regression that dropped the block would pass the lab's compare checks for any empty note. The server test `mcp-read-note-raw-body` does cover the two-block shape.
- **Issue acceptance #3 (a measured benchmark change) cannot be met by the premise benchmark**, which has no `read_note` path. The PR's measurement comes from a fixture (confirmed by my base-vs-head run above). Record this on #445 or in the Elara plan note when it is closed.
- **The ADR guarantee text needs a follow-up edit.** ADR-004 §2.1's `approxTokens(content[0].text) <= budget` is now stricter in practice (every block is counted), and the Elara ADR note is not edited. The PR says so itself under "Not covered".
