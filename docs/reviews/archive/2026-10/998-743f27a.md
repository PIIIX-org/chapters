## Findings (blocking)
1. **C++ out-of-line definitions get the outermost scope as `parent`** (`server/src/repositories/extraction-languages.ts:136`; P2, confidence 0.9).
   - Cause: `typeName(nameNode.childForFieldName('scope'))` reads only the first scope.
   - `void elara::Store::load(){}` gives `method elara.load`. Its in-class prototype `Store.load` is then not deduplicated, so the method appears twice under two parents.
   - In protobuf `descriptor.cc`, 105 of 388 methods have the wrong parent (for example `DescriptorPool.AddCheckpoint` instead of `Tables.AddCheckpoint`); in LLVM `APInt.cpp`, 14.
   - Fix: step into the innermost `qualified_identifier` before reading `scope`, e.g. `let q = nameNode; for (let i = q.childForFieldName('name'); i?.type === 'qualified_identifier'; i = q.childForFieldName('name')) q = i`, then `typeName(q.childForFieldName('scope'))`.
   - I checked this fix on a scratch copy: the wrong parents go from 105 to 0, the duplicate goes away, and the PR's 24 extraction tests still pass.
2. **Markdown files with any line over 1,000 characters lose their whole outline** (`server/src/repositories/extraction-queue.ts:482-486`; P2, confidence 0.85).
   - Cause: `sections` is gated on `!looksMinified`, a rule written for minified code. The docs say a file with such a line loses "symbols or imports"; they never mention sections.
   - In chapters, 11 Markdown files lose 314 sections, including `docs/agents/backend-reference.md` and `skills/*/SKILL.md`. In rea, 6 files lose 231 (199 of them from `CHANGELOG.md`).
   - Fix: `hasOutline(language) && (structured || language === 'markdown')`.
3. **The `skills/chapters` copy is out of sync** (`skills/chapters/references/mcp-tools.md:525`, `skills/chapters/SKILL.md:29`; P3, confidence 0.95).
   - The two `mcp-tools.md` files were identical on dev and now differ: only the elara one gained the new-language paragraph.
   - `skills/chapters/SKILL.md` still lists four languages, while its own header says the content matches the Elara skill.
   - Fix: apply the same edits to the chapters copy.
4. **Gates are red:**
   - **`attribution`** fails on `743f27a` because the branch still carries the stale stack commit `63b8f94`. Rebasing the #464 commits onto dev fixes it.
   - **`benchmarks/baseline.json`** is not updated. The all-suite gate on run 40193946217 says **Fail: vectorcraft stale baseline** (better than the baseline). There is no chapters or rea regression, which was the stated precondition, so the baseline can be recorded from that run.

## Minor
- **C++ headers named `.h` are parsed as C**, so a C++ header gets 0 symbols. leveldb `db_impl.h` loses `class DBImpl`; a 12-line test header gave 0 symbols as `.h` and 5 as `.hpp`. This is documented as a decision, but it costs most C++ codebases their class declarations.
- **C functions returning `**` are missed.** git `run-command.c` misses 2 of 72 definitions and `strbuf.c` 1 of 76. A two-level `pointer_declarator` pattern would catch them.
- **Macro annotations become methods.** leveldb's `GUARDED_BY(mu)` produces three false `method IterState.GUARDED_BY` symbols. This is a limit of the C++ grammar.
- **Docs promise searchable headings.** `README.md`, `skills/elara/SKILL.md` and `mcp-tools.md` call the headings "searchable" or "search blocks". No `search` leg reads `section` blocks (`search.ts:268` reads file blocks only, `:291` and `:307` symbol blocks only); today only semantic edges use them.
- **Embedding sections is costly with no retrieval use yet.** Index time on doc-heavy suites goes up 2–3× (chapters 243→689 s, diagram-design 182→447 s), while no search leg reads sections. Whether to defer embedding them until #414/#415 is a decision for you or the coordinator; the PR body already offers it as a one-line change.
- Small wording and coverage nits:
  - `embeddingNote` counts sections as "symbols".
  - The comment at `client/src/hooks/useCodeViewer.ts:33` still says "four languages".
  - Rust `mod x;` items are not recorded as imports.
  - Rust `use crate::{a, b}` is stored as the target `crate`, which never resolves.
