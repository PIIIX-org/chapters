## happy-dom 21 breaking changes vs the client test setup

I read the upstream v21.0.0 release notes (`gh release view v21.0.0 -R capricorn86/happy-dom`). The only breaking change is that **CSS file loading and iframe page loading are now off by default**. The `disableCSSFileLoading` setting is deprecated in favour of `enableCSSFileLoading` and `enableIframePageLoading`.

None of it touches this repo:
- **Vitest environment:** `client/vitest.config.ts` sets `environment: 'happy-dom'` with no `environmentOptions.happyDOM`. Vitest 5.0.3's environment code calls `new Window({ ...happyDOM, url: 'http://localhost:3000', settings: { ...happyDOM.settings, disableErrorCapturing: true } })`. The repo and vitest never set `disableCSSFileLoading` or anything related to iframes.
- **Setup file:** `client/src/test/setup.ts` only adds the jest-dom and vitest-axe matchers and runs `cleanup()` after each test. There are no `window` or `document` polyfills to break.
- **Call sites:** the client has no `<iframe>`, no `<link rel="stylesheet">` and no `createElement('iframe'|'link')`. The `getComputedStyle` assertions in `penNibCursor.test.ts` and `useCodeMirrorEditor.collab.test.tsx` read inline `<style>` rules injected by the theme, not external stylesheets, so the new default doesn't apply to them.
- **@testing-library:** `jest-dom` 7.0.1, `react` 16.3.3, `dom` 10.4.1 and `vitest-axe` 0.1.0 are unchanged. Only their peer-hash strings in the lockfile change.
- **Server:** happy-dom is only an optional peer of the server's `vitest`. The server tests don't run under happy-dom.
