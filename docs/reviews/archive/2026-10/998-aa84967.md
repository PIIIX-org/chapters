## Findings (blocking)
1. **In-class prototypes of a class declared as `class A::B {}` never deduplicate.** `server/src/repositories/extraction-languages.ts:95`
   - Cause: `containerName` returns `name.text`, so these methods get parent `DescriptorPool::Tables`. Their out-of-line definitions now get `Tables`, so `withoutDefinedPrototypes` never matches them.
   - Effect in `descriptor.cc`: 17 duplicate methods under two parents.
   - Fix, checked on a scratch copy: `return name ? (name.type === 'qualified_identifier' ? typeName(name) : name.text) : typeName(node.childForFieldName('type'))`.
     - `descriptor.cc` methods go 388→371, with 0 qualified parents left and still 0 wrong parents.
     - The PR's 39 extraction, import and find_symbols tests still pass.
2. **`.h` with the C++ grammar turns macro-prefixed C declarations into bogus methods.** `server/src/repositories/extraction.ts:387-388`, mechanism at `extraction-languages.ts:127-142`
   - Cause: tree-sitter-cpp recovers `CURL_EXTERN CURLcode curl_mime_name(...)` as `qualified_identifier(scope: CURLcode, MISSING "::", name: curl_mime_name)`. The qualified branch then emits `method CURLcode.curl_mime_name`.
   - Effect: 29 bogus methods across four headers that the C grammar read correctly at 743f27a:
     - curl.h: 19, and 16 real functions are lost;
     - zlib.h: 7, as `ZEXPORT.*`;
     - linux `list.h`: 2;
     - linux `kref.h`: 1, as `__must_check.*`.
   - It also contradicts `backend-reference.md:2602`, which says the C++ grammar "reads C declarations alike".
   - Fix, checked on the same scratch copy: before the qualified branch, add `if (nameNode?.type === 'qualified_identifier' && nameNode.children.some((c) => c?.isMissing)) nameNode = nameNode.childForFieldName('name') ?? nameNode`.
     - This gives 0 bogus methods in all the C headers; for example, zlib gains `zlibVersion`, `zError` and others as functions.
     - All tests stay green.
