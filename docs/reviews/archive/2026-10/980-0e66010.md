## Findings (blocking)
1. **Already-indexed `.mts`/`.cts` files are never fixed. The version bump marks them as current with no language and no symbols.** (P1, confidence 0.95; `server/src/repositories/extraction-queue.ts:317-321`, `language.ts:7-15`)
   - **How the old state survives:** `language` is written only by `syncRepositoryFiles`. When the content hash is unchanged, that function skips the row (`store.ts`, the `continue` on an equal `contentHash`), so a repeat poll or push never rewrites it.
   - **What the catch-up does:** `processFile` decides from the stored `row.language`, which is still `null` for rows indexed before this PR. So `isSupportedLanguage(null)` is false, and the catch-up extracts nothing. It still stamps `extractor_version = 2`, so the row will never be retried.
   - **Reproduction:** I ran a scratch vitest in my clone against the head. It recreated the pre-PR state (`language NULL`, `extractor_version 1`, no symbols or imports, version-1 job keys gone), then ran `scheduleMissingExtractions()` and `flushExtraction()`, then re-synced the same content. Result: `{"language":null,"extractorVersion":2,"symbols":[],"imports":[]}`.
   - **Why this blocks:** it contradicts the PR body ("indexed `.tsx`/`.mts`/`.cts` files get fixed without a push") and leaves #451 open for every existing repository. `.tsx` is unaffected, because those rows already had `typescript`.
   - **Fix (either one):**
     - In `processFile`, derive `const language = detectLanguage(row.path)`, use it for extraction, and write `language` in the same `UPDATE` that sets `extractorVersion`.
     - Or add migration 0034: `UPDATE repository_files SET language = 'typescript' WHERE language IS NULL AND lower(path) ~ '\.(mts|cts)$'`, keeping the `when` order after 0033.
   - In both cases, add a test that starts from a `language IS NULL` `.mts` row at version 1.
2. **CI did not run on the current dev merge.** CI, lab and bench ran on eec2ae8, which is 6ec2a87 merged into dev@44eb3d90. Dev has since moved to b367c6d (#964), and the tree differs. I ran the full suite locally on the current merge tree (results above), but the PR needs an update or re-run so that CI covers that tree. It will need one again once #978 lands.
