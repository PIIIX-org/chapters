**(1) #556**
- All five prompts that carry note text use `NoteBlocks`: `active_project_companion` (project and codebase notes), `prepare_task_context`, `test_gap_analysis`, `plan_feature_implementation` and `explain_code_architecture`.
  - A grep of `readNote`, `searchNotes` and `notes.add` finds no other prompt that does.
  - `summarize_concept_chain` puts node paths and ids into its instruction text. Paths are validated slugs (`resolveNotePath` → `isSlug`) and no note text is involved.
- The block shape matches the MCP spec's embedded resource: `{type:'resource', resource:{uri, mimeType:'text/markdown', text, _meta}, annotations, _meta}`.
  - The SDK 1.32.2 client parses it, and the tests assert `_meta` survives the round trip.
  - URIs are `elara://vault/<id>/notes/<slug>`, so no percent-encoding is needed.
- **Clients that drop resource blocks.** The note text lives only in `resource.text`; there is no text copy in the instruction message.
  - A host that ignores embedded resources in prompt messages would lose the note text.
  - It would still get the note paths in `[[path]]` form and the "attached after this message" wording, so the agent can `read_note` them.
  - I could not test this against a real client, and the spec allows `resource` content in prompt messages. See Minor.
