## Findings (blocking)

**`.github/workflows/ci.yml:89`: `--retry=1` can never rescue this test, so the PR does not fix the flake.**
- Vitest's `--retry` reruns only the failed test body. `beforeAll` and `afterAll` are not rerun, and the vault and providers persist.
- The only test, `server/test/collab-s3-perf.test.ts:78`, starts with `createNote(vaultId, { path: 'docs/big-typed', … })`. That path is hard-coded and the vault is shared across attempts.
- In `server/src/notes/store.ts` (createNote, ~lines 611-636), a unique-index violation is converted to `throw new NoteExistsError(...)`.
- So after a p95 miss like the 261.9 ms in run 41394097308, attempt 2 throws `NoteExistsError` before it measures anything. The step still fails, now with a misleading error. The queue entry is still ejected.
- The first attempt's three `HocuspocusProvider`s are also still connected, because `providers` is only destroyed in `afterAll`. Their debounced folds would add load to any rerun.
- To work, the test must be retry-safe: a unique path per attempt such as `docs/big-typed-${Date.now()}`, providers destroyed in a `finally`, and probably a fresh vault.
- I did not execute the test. This follows from reading the test source and the `createNote` conflict handling in the PR head. The PR's CI (`checks`) was still `IN_PROGRESS` when I looked.

## Minor
- The PR body says "a real regression fails both attempts". That is true in principle. As the code stands, though, every failure fails both attempts, including a transient one.
- The PR's `checks` and `fails-before` jobs were still `IN_PROGRESS` and the merge state was `BLOCKED`. The other checks passed or were skipped. The PR's CI result therefore can't show that the retry works.

## Verified OK
- **Vitest version:** `server/package.json` has `vitest ^5.0.5` and the lockfile resolves 5.0.5. `--retry` is a supported CLI flag.
- **Retry scope:** `--retry` is per test, not per file. The file has a single `it`, so there is no risk of retrying a whole file and passing on a different assertion.
- **Test unchanged, bound still 250 ms:** the PR touches only `.github/workflows/ci.yml`. `BUDGET_MS = 250` and `expect(p(0.95)).toBeLessThan(BUDGET_MS)` are untouched.
- **Cited run 41394097308:**
  - It was a `merge_group` run on `gh-readonly-queue/dev/pr-1065-…`.
  - The `checks` job failed on the step "Test collab-s3-perf alone (#905)".
  - The log shows `p95 261.9 ms` and `AssertionError: expected 261.8989669999992 to be less than 250`.
- **Policy fit:** the intent is a rerun at the same bound, not a weakened test. That fits the owner rule. A consistent regression would fail every attempt, so the retry would not hide one. The implementation just doesn't deliver the retry.
