## Findings (blocking)

1. **`server/src/search/search.ts:741-752` (`isCodeShaped`): the classifier misfires on ordinary prose.** Any single token triggers it.
   - `CODE_KEYWORDS` includes common English words: `type`, `class`, `method`, `module`, `package`, `import`, `export`, `return`, `let`, `async`, `impl`, `val`.
   - `PATH_SEPARATOR` fires on `and/or`, `Hopper/Ghidra`, `curl/wget`, `import/layering`, `host/platform`, `Node/V8`.
   - `CAMEL_OR_PASCAL` fires on product names and acronym plurals such as `WebAssembly`, `VectorCraft`, `GitHub`, `APIs`.
   - `SCOPE_OR_DOLLAR` fires on `$` and `()` anywhere.
   - I ran the classifier over all 109 benchmark questions. **63 of 109 (58%) are "code-shaped"** (chapters 16/29, context-mode 14/20, diagram-design 6/20, rea 15/20, vectorcraft 12/20).
   - Some of these are why/how questions about docs:
     - diagram-design Q14 triggers on "visual **type**".
     - diagram-design Q20 triggers on "**export**".
     - vectorcraft Q16 triggers on "`unwrap()`/`expect()`".
     - vectorcraft Q17 and Q20 trigger on "WebAssembly".
     - context-mode A3 (the gold is only `docs/adr/0001-…md`) triggers on `SessionDB`.
   - This contradicts the PR's claim that prose queries stay untouched.
   - Fix: require a real code signal.
     - Drop the generic keywords, or require keyword + identifier together.
     - Require a path to contain a known extension or ≥2 segments.
     - Require camelCase to be a single in-word case change that is not at the start of a prose word.
