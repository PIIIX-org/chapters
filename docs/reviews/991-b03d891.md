## Breaking changes in chokidar 6 checked against this repo

The repo has one call site, `server/src/repositories/local-watch.ts:58-65`: `chokidar.watch(localPath, { ignored: (path) => IGNORED.test(relative(localPath, path)), ignoreInitial: false })`, then `.on('all', …)` and `void watcher.close()`.

- **Glob removal:** not new in 6 (globs went in v4), and the repo uses none.
- **`ignored` signature:** unchanged. v6's `runtime.d.ts` still has `MatchFunction = (val: string, stats?: Stats) => boolean` and `ignored: Matcher | Matcher[]`. The new resolution of relative paths against `cwd` (#1436) applies only to string matchers, not functions.
- **`ignored` not applied above the watched path (#1374):** has no effect here. The function only tests paths under `localPath`, and #986 already returns `false` for `..` paths.
- **`awaitWriteFinish`, `interval`/`binaryInterval`, `usePolling`, `atomic`:** none are used. The new `TypeError` validation in the constructor has nothing of ours to reject.
- **`close()` is now terminal; `add()` after close throws:** the repo never calls `add()`. Both the head and #986 build a new watcher instead of reusing a closed one.
- **`getWatched()` returns a null-prototype object:** not used.
- **Errors from `add()` become `error` events instead of unhandled rejections:** missing paths (`isMissingError`) are still swallowed, so a deleted folder does not crash the server. See Minor for the remaining gap.
- **Default export and the `all` event:** both still exist (`export default { watch, FSWatcher }`, `EV.ALL`).
- **New `auto` backend:** it uses a native recursive `fs.watch` on macOS and Windows and per-directory watching on Linux. Docker and CI are Linux, so production keeps per-directory watching. On macOS the behaviour changes slightly (see the #986 section).
- **Node ≥ 22.22:** satisfied everywhere. Root `engines` is `>=24`, every workflow uses `node-version: 24`, and both Docker stages are `node:24-slim`.

## Interaction with #986 (open, head `129508a0`)

#986 rewrites `local-watch.ts` so that:
- `ignored` is a function `(path, stats?: Stats)`, backed by `GitignoreRules`, that falls back to `statSync` when `stats` is missing.
- When a `.gitignore`, `.git/info/exclude` or `.git/config` changes, it closes the watcher and builds a new one with `ignoreInitial: true`.

Findings:
- **Merge:** #986 merges onto #991 automatically. `server/package.json` and `pnpm-lock.yaml` auto-merge, `pnpm install --frozen-lockfile` passes on the combined tree, and `tsc --noEmit` is clean.
- **Tests on #991 + #986:** 5 files, **28/28 passed** on macOS (`repository-local-watch`, `repository-scan-rules`, which includes the test for un-ignoring a nested directory, `repository-skip-report`, `repository-scheduler`, `repository-skipped-file`).
- **#986's assumptions still hold under v6:**
  - The function signature is unchanged and `stats` is sometimes missing, so the `statSync` fallback is still needed.
  - The close-then-recreate pattern works: on both macOS and Linux the new watcher reports `change` and `add` in a nested directory that was un-ignored.
- **Platform difference:** I changed the `ignored` answer on a single watcher after `ready`, with no rebuild.
  - On **Linux** it emitted **nothing**, so #986's rebuild is still required on the Docker deployment.
  - On **macOS** it emitted `addDir`, `add`, `add`, because the recursive root watch re-evaluates `ignored` on each event.
  - So #986's doc sentence "chokidar never watches a directory it pruned" is true on Linux but not on macOS under v6. This is harmless: the rebuild makes behaviour correct on both. If the wording matters, it should be fixed in #986, not here.
- **Merge order:** either order works, and nothing in #991 needs to change for #986.

## Minor

- `local-watch.ts` registers no `error` listener, on the head or in #986. v6 routes more failures to `error` events, and with no listener a non-missing error such as `EACCES` or `EMFILE` throws from the emitter. Under v5 the `add()` failures were unhandled rejections, which crash the process too, so this is a gap that already existed, not one introduced here.
