## Findings (blocking)

1. **`benchmarks/baseline.json` is not re-recorded.**
   - The file is identical to #1064's, fingerprint `b94a4b13…` for chapters.
   - `HARNESS` hashes `benchmarks/run.ts` and every non-test file in `benchmarks/lib`. This PR edits `metrics.ts`, `policies.ts` and `run.ts`, so every suite's fingerprint changes.
   - The gate will therefore report stale baseline / suite changed.
   - The PR carries the `bench-suite-change` label, but the body has no `Bench-suite-change: <why>` line.
   - It also has no `routed` or `exact1Routed` numbers.
   - This is the same blocker #1064 had in round 1. Record the baseline from run 41336667436's three instances in this PR, and add the body line or drop the label.

2. **Ambiguous routed answers still count as exact@1.** `benchmarks/lib/policies.ts` (`run`, the `abstained` line) and `benchmarks/run.ts` (`outcome`).
   - `abstained` is `status === 'no_match' || status === 'ambiguous'`. The router answers `status: 'ok'` with a separate `ambiguous: true`, so `abstained` is never true for it.
   - #1064's review asked that hits of an ambiguous answer not count toward `exact1`. That is not satisfied for the only ambiguous answer that exists.
   - It is visible on the benchmark. `SearchResult` is defined in both `client/src/api/search.ts` and `server/src/search/search.ts` on current dev, and `parseNote` also in `client/mock/server.mjs`. This is dev, not the pinned commit 345f1db.
   - Results are ordered by path, so `client/…` comes first and S12 (gold `server/src/search/search.ts:32`) would likely score `exact1` 0. I could not confirm this against the pinned commit, and the bench run will show it.
   - A 15-of-15 `exact1Routed` is therefore unlikely on chapters.
   - Fix: read `ambiguous === true` from the parsed answer in `runElara`, and add a policies test.

## Findings (should fix, P2)

3. **More than 10 exact matches are truncated silently instead of falling back.** `router.ts`, the symbols query and the path `slice(0, MAX_ROUTED)`.
   - Both queries fetch `MAX_ROUTED + 1` rows, but the extra row is never used.
   - 11 or more matches return the first 10 by path with `ambiguous: true` and no fuzzy hits. The file comment says "more than this is not an answer", and the docs say "all listed".
   - Common one-word queries are the trigger: `index.ts`, `handler`, `get`, `config`, `run`. In a real repository they would replace the hybrid results with an arbitrary path-ordered subset.
   - Fix: if the overflow row exists, return `null` so the hybrid path runs, or flag the answer as truncated.

4. **A backticked term overrides the verbs around it, so a caller or test question gets the definition at `confidence: 1`.** `routeTerm`.
   - Any query of at most 6 words with exactly one backticked token is treated as "where is X defined".
   - `who calls \`searchNotes\``, `tests for \`parseNote\``, `references to \`X\`` and `how does \`retry\` loop` all return only the definition, with no hybrid results.
   - Those are the issue's own structural examples. Their unquoted forms fall through to hybrid (the filler words do not cancel them), so behaviour depends on whether backticks were used.
   - Fix: apply the backtick rule only when the rest of the query is filler.

5. **A routed answer drops the `index` block.** `search.ts`, the early return.
   - `state = indexState(…)` is started before the router. A routed answer never awaits or attaches it, and still says `status: ok, confidence: 1`.
   - The docs say hits found while indexing goes on are `ok` with `index` shown. A symbol defined in a file still waiting for extraction is reported as exact and unambiguous with no warning.
   - It also runs two queries whose result is thrown away.
   - Fix: await `state` and include `index` when any count is non-zero.

## Minor
- `client/src/api/search.ts:29` still types `retrieval_mode` without `'exact'`. The REST routes and the UI overlay are routed too, so typing a three-letter word that is also a symbol name returns only that symbol.
- The `mcp-tools.md` **Returns** line `{ status, retrieval_mode, degraded, index?, results, truncated }` does not list `route`, `confidence` or `ambiguous`.
- The path query reads the full `f.content` of up to 11 files just to count lines and tokens. The `LIKE '%/name'` and `lower(CASE…)` predicates have no supporting index, so both do a scan within the scoped repositories.
- Paths are not normalised: `./src/x.ts` and a leading `/` fall back to hybrid.
- The path route's `exact1` is trivial. Whole-file lines 1..N overlap any gold in the file, so it will inflate `exact1` and `exact1Routed` on path questions. Read it together with tokens.
