## Findings (blocking)
1. `.githooks/prepare-commit-msg:26-29` — an aborted editor commit no longer aborts; it commits a message that is only the trailer.
   - **How I ran it:** I set `GIT_EDITOR` to a script that leaves the buffer untouched, then ran `git commit` (staged file, no `-m`).
   - **Without the hook:** `Aborting commit due to empty commit message.`, exit 1.
   - **With the hook:** exit 0 and a new commit whose subject is `Co-Authored-By: Claude Opus <noreply@anthropic.com>`.
   - **Cause:** the hook prepends the trailer to an otherwise empty message, so git's empty-message check no longer fires.
   - **Impact:** any editor commit where the user quits without typing, or clears the buffer, creates a junk commit with no subject. That is a regression from stock git for every editor commit.
   - **Fix:** do not touch an empty message in `prepare-commit-msg`. Add the trailer in a `commit-msg` hook instead. It sees the final cleaned message, can skip when `git stripspace --strip-comments` is empty, and also covers `-m`. I have not tested a `commit-msg` variant, including on merges.
2. `.githooks/prepare-commit-msg:26,31-32` — under `git commit -v` or `commit.verbose=true` with the editor, the trailer lands directly under the subject, and the `attribution` check does not count it.
   - **Cause:** with `-v` the message file holds the scissors line and a diff, so `git stripspace --strip-comments` returns non-empty. The hook skips the "empty message" branch and `interpret-trailers` appends the trailer after the one blank line at the top of the file.
   - **Result:** the editor shows line 1 blank, line 2 `Co-Authored-By: …`, then the comments. After the user types a subject on line 1, the commit message is `subject\nCo-Authored-By: …` with no blank line.
   - **Impact:**
     - `git log --format=%s` gives `verbose subject Co-Authored-By: Claude Opus <noreply@anthropic.com>`, and `%(trailers)` is empty.
     - The repo's `attribution.trailers()` needs at least two paragraphs, so this commit fails the `attribution` check the hook exists to satisfy.
     - The same `-v` abort case also commits (the finding 1 behaviour).
   - **Fix:** the `commit-msg` approach in finding 1 resolves this too.
