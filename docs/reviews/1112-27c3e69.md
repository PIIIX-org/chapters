## Findings (blocking, path:line)

1. **`server/src/mcp/orient.ts` (the `sections` array at the end of `orientAnswer`): on a repository with more than 10 root entries, the first page returns an empty `symbols` list.**
   - The PR puts `folders` and `outline` before `symbols`. `fill()` in `response.ts` ends the page at the first keyset list that has more (`if (slot.more && keyset) return {stop: n}`). Every later section keeps `shown[n] = 0`. A `symbols` list that is cut off this way is still emitted as `[]`, with `truncated.total.symbols: ">10"`.
   - `folders` is the list of folders and files one level below `path`. Most real repositories have more than 10 of them at the root, and so does any vault `outline` with more than 10 entries.
   - Before the PR, the first page showed both `symbols` and `folders`. Now the main answer, the ranked definitions, is reachable only after paging through every `folders` page. With a vault in scope, `outline` hides the symbols in the same way.
   - The PR's own text admits that a list after the continued one repeats from its start. The new test does not catch this. Its 25 files all sit under `src/`, so `folders` has one entry and never reaches 10.
   - Fix: keep `symbols` first, since it is the main answer, so it is not cut off by `folders`. Then make `folders` and `outline` pageable on their own, or show them before `symbols` capped at the ten with no `more` page-ending behaviour. Add a fails-before test with at least 11 top-level folders that asserts `symbols` is non-empty on page 1.

2. **`server/src/mcp/orient.ts`: offset cursors have no guard, and `repositoryId` is not part of the cursor binding.**
   - `UNBOUND_ARGS` in `response.ts` includes `repositoryId` and `vaultId`. A cursor issued for repository A can be replayed with `repositoryId: B`, which returns B's list at A's offset instead of a stale-cursor error.
   - The section index also shifts with the scope, because it is built from `repos.length` and `vaultIds.length`.
   - The PR calls the re-index skip and repeat case "Not covered" but does not mention this. I rate it blocking only because the review brief asks that paging stay scoped to the repository. If you decide a re-index between pages is acceptable, this can be downgraded.
   - Fix: bind the repository, for example through the keyset `resume` token, or pass a guard as `ranked` does with `rankedGuard`.

## Minor

- **Ranking is sound and documented.**
  - `textual` edges only get a target when the name is unique (`code-edges.ts:323`), and members of an unknown receiver are excluded. The half weight is therefore reasonable.
  - The ranking order is deterministic: `score DESC, path COLLATE "C", line, block_id`, and `child COLLATE "C"` for folders.
  - It is documented in the `repositories/orient.ts` header, `backend-reference.md` and the manuals.
  - The `0.5*` weight and the choice of which edge kinds count are not justified by any measurement.
- **Budgets:** the schema and description are unchanged. The only handler change is passing `page` through, and `cursor` is already in the budget wrapper's schema. The answers gain only a `guessed` field. No new read surface, so the access matrices need no change.
- **Manuals:** both `skills/*/references/mcp-tools.md` have the same blob hash (`b4761a8d`), so they are identical.
- **Fails-before:** the `fails-before` job passed. An earlier run of it was cancelled.
- **CI:** `review-verdict/dev` fails only because no VERDICT comment exists for this head yet. `checks` and `bench (1)` to `bench (3)` are still pending. `lab` passed.
- **#534 done-when:** the benchmark change is "once the benchmark exists", and the bench jobs are pending. The Elara plan note is not visible in the PR.
- **Test coverage:** there is no test for paging a list other than `symbols`, none for multiple repositories or a vault, and none for the `guessed` ranking below resolved uses.
