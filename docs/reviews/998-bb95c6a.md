## New findings

**`server/src/repositories/extraction-languages.ts:127-130`, also `:234-236` (P2, confidence 0.85): a macro-prefixed declaration with a pointer return is still lost in `.h`.**
- `CURL_EXTERN curl_version_info_data *curl_version_info(CURLversion stamp);` (curl.h:3249) is found by the C grammar but not by the C++ grammar, before or after this fix.
- tree-sitter-cpp reads it as `declaration declarator: (qualified_identifier scope: (namespace_identifier) (MISSING "::") name: (pointer_type_declarator declarator: (function_declarator declarator: (type_identifier))))`.
- No `cFunctions` pattern matches a `qualified_identifier` that wraps a `pointer_type_declarator`, and the function name there is a `type_identifier`. So the new MISSING check never runs and the function is dropped.
- A likely fix, which I haven't tested: add a C++ declarator pattern `(qualified_identifier name: (pointer_type_declarator declarator: (function_declarator declarator: (type_identifier) @name)))`, plus a test line like `CURL_EXTERN curl_version_info_data *curl_version_info(CURLversion stamp);`.

A side note, not blocking: the check also runs on protobuf `descriptor.h`. There, 12 in-class `PROTOBUF_FUTURE_ADD_EARLY_NODISCARD T f()` declarations go from bogus `int32_t.default_value_int32_t`-style methods to module-level functions. tree-sitter-cpp already mis-parses that header (its `namespace google` ends at line 381 of 3,463).
