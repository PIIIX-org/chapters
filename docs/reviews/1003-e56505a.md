- **Line and context come from the stored rows.** Each backlink is built from `note_links` (start and end line, plus the new `context`). `location` is `path#La` in the linking note's whole `.md` file, using `bodyStartLine` as `edges.ts` does. The tests check this against lines found in the projected files, including after a frontmatter-only edit.
- **Context size is bounded.** `contextWindow` and `fits` cap it at 200 code points, with `…` taking the place of a cut code point. It never splits a surrogate pair (tested at four offsets) and drops the `\r` of CRLF lines.
  - Paragraphs longer than 800 UTF-16 units are never assembled.
  - Timing on the extractor: 20,000 links on one 329 KB line took 40 ms, versus 9 ms spread over many lines. That is not quadratic.
  - The list is capped at 1,000 items (1,000 + 1 are fetched), and the budget envelope pages the answer.
- **Account separation holds.** `backlinksOf` filters on `notes.vaultId = center.resourceId`, live notes only, and excludes the centre itself. I confirmed this with a throwaway MCP probe, since deleted:

  - A's backlinks listed only `a/linker`, and B's text never contained A's marker or the reverse;
  - A asking for B's vault got `NOT_FOUND`;
  - an account-scoped call without `vaultId` is refused, so one call never spans vaults.
  - There is no finer path-level scope in `server/src`.
- **No new tool and no new parameter.** The `graph` input schema and description are unchanged, so the tools/list delta is 0. `mcp-tool-budget` (reader ≤ 2,000 tokens, ceiling 43,000) and `mcp-tool-schema` pass on the merge.
