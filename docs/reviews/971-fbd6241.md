## Findings (blocking)
1. **Reverting to a revision from before a move stamps the old folder as the note's type (P2, confidence 0.9).**
   - **Where:** `server/src/notes/store.ts:961`, through `revertNote`.
   - **Cause:** `revertNote` passes the old revision's whole frontmatter to `updateNote`/`writeThroughCollab`. Before this PR, those functions overwrote `type` with `row.type`. Now `withType` keeps whatever `type` the old revision had.
   - **Reproduction (my scratch test):** create `drafts/rv`, `rename_note` to `specs/rv` (the type becomes `specs`, as intended), then revert to the `create` revision. The result is `notes.type=specs` but `frontmatter.type=drafts`. The same test on dev gives `specs`.
   - **Impact:** the stale folder name now counts as a semantic type. Later moves keep it, because `moveNote` only rewrites a type equal to the current folder. `index.md` and the type pill show `drafts` from then on.
   - **This contradicts the PR's own rule** that a folder-valued type follows the note.
   - **Possible fix:** in `revertNote`, when the revision's `type` equals the folder the note had at that revision, use `row.type`. That folder can be derived from the `from_path` of the rename revisions recorded after it. Also add a revert-after-move test.
