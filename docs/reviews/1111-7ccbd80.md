## Minor
- **No route-level rate limit.** The three routes (`grep-routes.ts`) are covered only by the global 1000 requests/min per IP limit in `app.ts`. MCP grep is throttled to 120/min per connection by `mcp/rate-limit.ts`. Each REST call can hold a transaction for up to 4 s per statement and 10 s per scan. Neighbouring read routes such as `/search` have no per-route limit either, so this is consistent with the existing REST routes. A `config: { rateLimit }` on these routes, as `sync/routes.ts` does for `/collab/ticket`, would be a cheap guard.
- **Oversized `after` cursor may return 500 instead of 400 (not run).** `parsePosition` accepts any digits, so a huge line number or a NUL byte in `after` or `pattern` would reach SQL parameters and probably raise a Postgres error that surfaces as 500. The MCP tool has the same behaviour, which this PR did not introduce. The route can now be reached directly with hand-written cursors, so a bound on the digits would be worthwhile.
- **`/api/grep` with one reachable target omits the source id.** The hit's `vaultId` or `repositoryId` is left out because `targets.length === 1`, and `commit`/`tree` is returned only on the repository route. MCP behaves the same way, so this is parity rather than a bug.
