2. **One `read_note` with missing heading targets blocks the event loop for seconds.**
   - `server/src/mcp/read-targets.ts`, `nearestPaths` (about lines 110-129), reached from `named` for every NOT_FOUND heading or symbol.
   - Each missing target computes `editDistance` (an O(n·m) loop that allocates a row per character) against every distinct path, each cut to 200 characters. The handler runs this synchronously.
   - Measured: a 240 KB note with 2,000 headings and 20 missing 200-character heading targets took 14.7 s in the pure function and **15.4 s end-to-end** through a reader token's `read_note`. A 610 KB note with 5,000 headings took 38.6 s. A single typo on the 2,000-heading note cost 179 ms.
   - Any `read`-access token can stall the shared server (MCP, REST and collab) this way. The repo already guards the same pattern for unknown keys (#769: `suggestion()` skips keys over 64 characters).
   - Fix: bound the comparison. For example, compare only short `want` values, cap how many candidates go through edit distance after the tier pre-sort, or cap the total work per call.

## Minor
- **The budget range is no longer visible to agents.**

  - Either add it to the reader instructions (there are about 20 characters of margin) or correct the comment.
- **The "a changed note refuses the cursor" comment is false for targets.**
  - `server/src/mcp/server.ts:1393-1395` says it, but a targets cursor's guard is the hash of that part's own text (`response.ts:346`).
  - An edit elsewhere in the note lets the cursor continue at the new rev, and that rev is recorded.
  - After an insertion above a heading target, page 2's `lines` no longer line up with page 1's `next`.
- **Quadratic outline build**: `markdownParts` runs `found.find` once per heading over all blocks. That is 120 ms at 5,000 headings and 510 ms at 10,000, on every outline or targets read of such a note. Index the blocks by `startLine` instead.
- **Duplicated body-start logic**: `body_start_line` is computed by its own `serializeNote` slice instead of reusing `bodyStartLine()` in `notes/projector.ts`, which graph edges use.
