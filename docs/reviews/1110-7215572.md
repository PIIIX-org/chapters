# Review of PIIIX-org/chapters#1110

Head reviewed: 0d251da77fda27743736a40782f5e037db16b63a

## Scope checked
- Edge formatting, including undirected edges, null evidence and missing names.
- Output bounds, name scope and determinism.
- Whether the new test fails before the fix.
- Whether #558 is complete.
- Token budgets and the prompts listing.
- Docs.
- CI.

## Verified
- **Formatting:**
  - Steps print `[type] path` and edges print `from -> to (relation, kind, confidence[, evidence])`.
  - `--` is used when an edge is undirected.
  - A null `evidence` drops the trailing field cleanly.
  - Path nodes are always in the node set passed to `edgeRows`, so the `node()` lookup cannot fail.
  - The `r.directed ? '->' : '--'` branch has no test. The new test only covers a directed link edge.
- **Failure handling:** `pathInfo` is only assigned after `edgeRows` resolves. If it throws, the surrounding `catch` leaves the prompt without a path section, the same as before the patch.
- **Names:** every name comes from `path.nodes`. Those nodes come from `buildGraph(resources)`, and `resources` is the single vault that `requireAccess(vaultId, 'read')` just checked. `edgeRows` only adds a vault or repository label when `resources` spans more than one, and here it never does. Ids are no longer printed.
- **Bounds:** the output is one line per hop of the BFS shortest path. Evidence is `path#La-Lb`, a structural group key, or null. It is never note body text.
  - Edge count is bounded only by the shortest-path length. Before the patch it was bounded the same way.
- **Determinism:** the BFS order follows `graph.edges` order. `edgeRows` keeps edge order and sorts the ends of undirected edges by code unit. The patch adds no nondeterminism.
- **Fails-before:** the PR body says the new case fails on dev's `prompts.ts`. The `fails-before` check passed.
- **#558:** the issue status comment says `graph`, `find_graph_path` and the #470 tools were already delivered, and that this prompt is the only gap. The patch closes that gap.
- **Token budgets and listing:** the prompt `title`, `description` and `argsSchema` are unchanged, so `prompts/list` is the same. The reader, writer and admin tool budgets are not affected.
- **Access matrix and `mcp-tools.md`:** no new read surface is added, so neither access-matrix file needs a change. No `mcp-tools.md` file is touched, so the two copies stay identical.
- **Test fixtures:** the two extra notes are created in `beforeAll`. The prompts-count assertion (`toBe(20)`) is unaffected, and I saw no other assertion on note counts.
- **CI:**
  - Passing: `lab`, `fails-before`, `plan`, `pr-evidence`, `evaluate` and `issue-close`.
  - Pending: `checks` and the `bench (1/2/3)` jobs. I did not wait for them.
  - Failing: `review-verdict/dev` fails only because no review of this head has been posted yet.

## Findings (blocking, path:line)
1. **`docs/agents/backend-reference.md:1304`** is not touched, and after this patch it is false. It says: "`mcp/prompts.ts`'s path prompt still prints ids." The owner rule is that a permanent fix updates the docs. Change that sentence to say the prompt now prints `edgeRows` rows by path, with `--` for an undirected edge. The diff has no docs change.

## Minor
- The test does not cover the `--` branch or a null `evidence` field. A structural or undirected pair in the fixture would exercise both.
- The prompt prints one line per hop with no cap. This was already true before the patch.
- Merge when `checks` is green. The `bench` jobs are still pending, and I did not wait on them.

   - Fix: assert the real structural line, e.g. `(same_type, structural, resolved, type:chain)`, for the `--` case. Cover the null-evidence branch with a semantic or null-line edge, or with a unit test on the formatter. Extracting the row formatter into a small pure function would make both cases directly testable.
   - Because Finding 1 stops the run before tests, this has not been seen to fail in CI. The fails-before check passed, but it only shows the first test's assertions differ from `dev`.
