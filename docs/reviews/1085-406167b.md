**ORDER BY is total for the tie that occurred.** `server/src/repositories/grep.ts:291-301` sorts by span length, then `KIND_RANK`, then `innerPath`, then `block` id. For the #1083 tie, a file block and a symbol block with one span, the kind decides: symbol is rank 0, file is rank 4. That does not depend on id or row order.

- **Skeleton.** A class's skeleton block has the same span as its symbol, and symbol still comes first. A file-wide skeleton against the file block resolves as skeleton before file.
- **Code blocks.** Two blocks can share span, kind and inner path only for exact duplicate declarations. Even then the id decides, and `siblingIndexes` gives them distinct ids.
- **Note blocks.** A note's blocks share kind and inner path only as chunk pieces of one section. Those pieces have disjoint line ranges (`note-blocks.ts:41-73`), so they never both hold a line. Duplicate headings give different spans. So the id is a last resort that is practically never reached.
- **Refactor.** The new mapping replaces `markdownParts` and `codeParts`. It keeps the same `endLine >= startLine` filter and the same `+offset` shift for notes, so hit lines and blocks are unchanged apart from carrying `kind` and `innerPath`. The `rangeTokens` import is still used.
