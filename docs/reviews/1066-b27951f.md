## Findings (blocking)
1. **The benchmark evidence is not for this head.** The pair was measured at 37bddca. The head has since added the dev merge and b27951f, which changes how snippets are produced, and its own bench run is still pending. Owner rules need the same-base all-suite pair with `--require-golds` on the head, so the pair must be re-run at the final head after rebasing onto dev.
2. **Not every hit gets a passage, and the issue's "instead of whole documents and frontmatter" is not met.** This matters because the PR says `Closes #414`.
   - `locate.ts` ends a code-file hit with `if (!place) continue`. A vector-only code hit whose query terms do not appear literally gets no `startLine`, `endLine`, `block` or `tokens`, and keeps the old `left(content,200)` snippet.
   - Likewise a note over 262,144 characters, and a vector-only note hit whose block is known, get nothing because the body is not read (`row.body === null`). The vector leg already carries the block there.
   - Frontmatter is still returned (deferred to #419), so the issue text is only partly delivered. Either narrow the closing claim to "Refs #414" or finish these cases.
3. **`bestPlace` and the bulk body reads cost too much at large limits.** Each located hit does `hits × hits` work (up to 200 occurrences per term, so about 1,600 entries for 8 terms, each building a `Set`). It also reads whole bodies and file contents, up to 256 KB each, for every returned hit. The MCP tool fetches `limit + 1` up to 101 hits. Under a 100-hit search this means tens of MB read and on the order of 10⁸ operations on the event loop, which #1052's lag alerts would flag. This work is also not observed in the new search-leg histograms. Cap the candidate list, or use a sliding window over the sorted hits instead of the quadratic scan. I did not run it, so the magnitude is an estimate.

## Minor
- **Tokens-to-gold went up, not down.** chapters rose +3.8 % with the extra fields on every hit, and `no_context` strips only snippet, frontmatter and updated. Block, heading, tokens, channel and lines all stay on the page, which makes full hits larger, so the ladder will step down sooner at the default 2,000-token budget. Owner target is minimal tokens, so this needs #1064 to repay the cost.
- **`locations` rung changed for notes and files.** It now emits `path#La-Lb` for every hit with lines, where notes and files used to give bare `path`. That is probably intended, but it is undocumented in the manual and no test covers it. Note paths that now carry `#L…` also drop the `block` id.
- **`bestPlace` index drift.** `text.toLowerCase()` can change string length (for example `İ`), so indices drift from `lineStarts(text)` for such text.
- **Short query words dropped.** `matchTerms` drops plain words under 4 characters ("API", "RAG"), so a short-acronym query gets no located place.
- **Snippet cut loses a word.** `snippetAround` always drops the first word of a cut that starts mid-text, even when the cut begins exactly on a word boundary.
