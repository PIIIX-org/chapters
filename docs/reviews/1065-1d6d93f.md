## Findings (blocking)

1. **The lock is bypassed by removing or renaming the suite.** `.github/scripts/bench-gate.mjs:225` iterates only `results.selected`, and nothing requires the base baseline's suites to be present in the run.
   - A PR touching `server/src/search/**` can delete `benchmarks/questions/holdout.json`, or change its `suite` field so the name is no longer `holdout`. The `holdout` row is then never evaluated.
   - That means no lock, no regression check and no gold floor for it.
   - I probed the gate with the head's own code. Base has `s` and `holdout`, the PR run has only `s`, `changed=['server/src/search/search.ts']`, `requireGolds=true`. The result is `ok: true` with no failures.
   - Fix: when `baseBaseline` has `holdout` and the run lacks it, fail. Failing for any base suite missing from the run is simpler and safer. In `evaluate`, loop over `new Set([...results.selected, ...Object.keys(baseBaseline?.suites ?? {})])` and fail on any base suite missing from `results.suites`. Add a unit test.

2. **Merging is not possible yet because no `holdout` baseline exists.**
   - `baseline.json` has no `holdout` entry (grep count 0).
   - The body says the gate is red here until the entry is recorded after #1064 lands.
   - Recording it needs all six entries regenerated, because `run.ts` changed and moved every fingerprint.
   - The recording must come from the final harness, with the `bench-suite-change` label that is already on the PR.
   - So the PR cannot enter the queue as-is. Re-review once the baseline commit and its three-instance run exist.

## Minor
- **Narrow lock paths.**
  - The lock covers only the three paths named in the issue. The `--require-golds` set is wider: extraction (`repositories/{extraction,code-blocks,…}`), `text/{blocks,lines,targets}`, `note-blocks` and `config.ts`. Those paths change what is retrievable, and a PR touching only them can still write or raise the `holdout` baseline.
  - A rename that moves code out of the three paths shows only the new filename in the file list, which also escapes the lock.
  - I would add the extraction and config paths to `RANKING_PATHS` and match `previous_filename` too. This is outside the letter of #1059.
- **Tolerance on `holdout`.** The existing one-question slack on `hit5`, `exact1` and `goldReachedRate` still applies. Only `goldReached` under `--require-golds` has zero tolerance.
- **Plain-text gold.**
