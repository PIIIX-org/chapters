## Findings (blocking)
1. **`server/src/mcp/routing-hints.ts:40` — the `rg` command in the hint is not shell-safe.**
   - The hint is a command meant to be pasted, built as `rg -n -F ${JSON.stringify(literal)}`.
   - A JSON-quoted string is not a safe shell argument. The `code` rule (line 37) fires on `$`, so queries like `$(cmd)`, `${HOME}` or `$var` match. In shell double quotes `$(…)` runs a command, and `${HOME}` and `$var` are expanded before `rg` sees them. The literal is then wrong, or `rg -F ""` matches every line.
   - Backticks and `!` have similar problems.
   - A literal that begins with `-` (e.g. `"-x"` or `--foo()`) is parsed as an `rg` flag because there is no `--`.
   - The hint names a command that gives wrong results, or runs something, for the very inputs the rule is meant to catch.
   - Fix: build a single-quoted argument (`'` → `'\''`), pass it after `--`, and send the hint only if the literal is representable. Or drop the literal and keep the generic `rg -n -F <text>`.
2. **`server/src/mcp/routing-hints.ts:37` — the code-punctuation test is too broad and sends prose to `rg -F`.**
   - Any query of at most 80 characters containing `( ) { } [ ] < > = ; \ | ^ $ * +` counts as "exact text". Examples: `how does retry (backoff) work`, `why is a=b slow`, `C++ vs Rust`, `what does the * operator mean in rg`.
   - These are meaning questions Elara answers well. The hint tells the agent they are "exact text, not meaning" and to run `rg -F` on the entire sentence, which returns zero matches.
   - This pushes agents to a worse tool plus a wasted call, against the issue's "hint never replaces an answer Elara can give cheaply".
   - The unit table covers only punctuation-free prose and so misses this.
   - Fix: require more than one punctuation character with no spaces (identifier-like or call-like tokens), or require the query not to look like a sentence (for example fewer than N word-like tokens).

## Minor
- `server/src/mcp/server.ts` (read_note and read_file call sites): the hint is attached before `inSession`, so a long text re-read from the top under `session_id` gets the ~30-token hint even when the body is a `same_as` reference of a few tokens. It makes that answer larger for no gain.
- The outline hint fires on any file over 400 lines, including ones with no structure (JSON, lockfiles, logs). Their outline is empty, so `outline: true` then `targets` costs an extra round trip. An unstructured file would be better served by `targets: lines`.
- A `'` or `` ` `` quote counts as "quoted" for the whole query, so a short quoted prose phrase also gets the `rg` hint.
