## New findings

**1. The watcher misses edits in a nested directory that a `.gitignore` change un-ignores (P2, confidence 0.85).** `server/src/repositories/local-watch.ts:74-78`
- **What happens:** chokidar applies `ignored` once, when it first sees a path, and never watches a pruned directory. `rules.clear()` changes the answer for future calls, but chokidar only re-reads a directory when that directory itself changes.
- **Probe on head:**
  1. Set the root `.gitignore` to `a/b/gen/` and start watching.
  2. Rewrite the `.gitignore` to remove that line. One sync runs and indexes `gen/`.
  3. Edit `a/b/gen/a.ts`: no sync. Add `a/b/gen/new.ts`: no sync. Edit a root file, then `a/b/gen/a.ts` again: still no sync.
  4. With `gen/` directly under the root, the root's re-read happened to catch it.
- **Impact:** local_path repositories have no poller; the scheduler's `tick` covers only `ingestionMethod = 'git'`. The index goes stale for that directory until the server restarts or someone syncs by hand. On the base, everything except `.git` and `node_modules` was watched, so this is a regression.
- **Docs:** the claim "The watcher rereads the rules when a `.gitignore` changes" doesn't hold for this case.
- **Fix:** when a `.gitignore` event arrives, close the chokidar watcher and create a new one with `ignoreInitial: true` after `rules.clear()`. That makes chokidar re-evaluate `ignored` across the whole tree. Add a test for a nested un-ignore.

**2. `ignore()` matches case-insensitively by default, unlike git on Linux (P3, confidence 0.6).** `server/src/repositories/fs-scan.ts:75,86`
- **What happens:** both `ignore()` calls use the library default `ignorecase: true`. Git's `core.ignorecase` defaults to false on Linux, which is where the Docker deployment runs.
- **Probe:** a `.gitignore` of `/Data/` and `*.LOG` skips `data/x.ts` and `a.log` as `ignored`. With `core.ignorecase=false`, `git check-ignore` matches neither and `git status` lists both.
- **Impact:** source is silently dropped from a local folder, which is the kind of loss #465 is meant to stop. It also contradicts the docstring "as git applies them".
- **Fix:** `ignore({ ignorecase: false })` in both places, or read `core.ignorecase` from the folder's `.git/config`.
