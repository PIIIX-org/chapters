## Verified
- **Edges:** four kinds in `code_edges`: `call`, `reference`, `import` (a name an import binds) and `test` (one row per distinct non-local name a test file uses).
  - TS/TSX/JS, Python, Go, Rust and Java get all of calls, references and symbol-level imports.
  - C, C++, C#, Kotlin, Ruby and PHP get calls only.
  - The test edges come from a path convention.
  - The PR drops calls into each language's own library, which goes beyond the issue's spec and which the PR flags itself. The lists are hand-written per language.
- **Resolution** is tree-sitter and per-language, with no type inference:
  1. same-file definition;
  2. the file the binding import resolves to;
  3. the same Go or Java package;
  4. the repository's unique definition of the name, stored as `textual` with a target;
  5. otherwise `textual` with no target.
  - Python and Go module specifiers don't resolve to files, so their cross-file edges are `textual`. The PR says so.
