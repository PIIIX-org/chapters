Critical SEC-01 Stored Cross-Site Scripting (XSS) via Mermaid Live Preview ('securityLevel: loose')
✓ FIXED CVSS 9.6 CWE-79 ▼
Vulnerable File client/src/hooks/mermaidDecorations.ts:13
Component CodeMirror Mermaid Live Preview Extension
Attack Vector Network / Stored Note Markdown
CVSS v3.1 Vector CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:H/A:H
📌 Vulnerability Description

When a user views or edits a note containing a ```mermaid block, the live preview decoration renders the diagram dynamically using Mermaid.js. In mermaidDecorations.ts, Mermaid is configured with securityLevel: 'loose'. The resulting SVG markup from mermaid.render() is then assigned directly to the DOM using viewport.innerHTML = svg without sanitization.

⚡ Vulnerability Mechanics & Attack Flow

Under securityLevel: 'loose', Mermaid explicitly turns off its built-in HTML encoding and DOMPurify sanitizer. A malicious user with edit access to any shared vault (or submitting a Git repository containing an OKF documentation note) can craft node text containing unescaped HTML elements such as <img src=x onerror=...> or click directives. When another user (including administrators or owners) opens the note in the editor, the code executes immediately in the context of the user's browser session.

💥 Impact Analysis

Arbitrary script execution within the application origin. The attacker can execute authenticated API requests on behalf of the victim (e.g. read/write all accessible vaults, trigger account role escalation, bypass MFA, or exfiltrate private notes and credentials).

🛠️ Remediation & Patch

Change securityLevel to 'strict' (or 'antiscript') in mermaid.initialize(). Strict mode forces Mermaid to escape HTML entities in labels and disallows JavaScript click events.

Critical SEC-02 Stored Cross-Site Scripting (XSS) via Unrestricted SVG Asset Upload & Inline Execution
✓ FIXED CVSS 9.6 CWE-79 / CWE-434 ▼
Vulnerable File server/src/notes/routes.ts:324-335
Component Vault Asset Serving Handler & MIME Store
Attack Vector Network / Asset Upload
CVSS v3.1 Vector CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:H/A:H
📌 Vulnerability Description

The asset upload endpoint POST /vaults/:id/assets permits users with edit access to upload arbitrary SVG image files (mapped to image/svg+xml via ASSET_MIME_TYPES). The download endpoint GET /vaults/:id/assets/:fileName serves this content buffer directly with Content-Type: image/svg+xml, without setting a download Content-Disposition: attachment header or applying a sandboxed Content-Security-Policy.

⚡ Vulnerability Mechanics & Attack Flow

An attacker uploads an SVG asset containing embedded JavaScript (e.g. <svg xmlns="http://www.w3.org/2000/svg"><script>fetch('/api/me')...</script></svg>). When a victim clicks the asset URL or navigates directly to /api/vaults/:id/assets/:fileName, the browser renders the SVG XML document natively in the application's domain and executes the embedded script within the authenticated origin.

💥 Impact Analysis

Same-origin session compromise, silent vault modification, account takeover, or credential harvesting.

🛠️ Remediation & Patch

Enforce Content-Disposition: attachment on SVG and HTML asset responses, and inject a strict Content-Security-Policy: default-src 'none'; sandbox header so browsers cannot execute scripts even if inline rendering is forced.

Critical SEC-03 Server-Side Request Forgery (SSRF) and Git Argument Injection via Unvalidated 'gitUrl'
✓ FIXED CVSS 9.1 CWE-918 / CWE-88 ▼
Vulnerable File server/src/repositories/git-sync.ts:45, routes.ts:103
Component Repository Ingestion & Git Sync Engine
Attack Vector Network / API Input (gitUrl)
CVSS v3.1 Vector CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:N
📌 Vulnerability Description

When adding a repository via POST /api/repositories or the MCP connect_repository tool, the gitUrl property is validated only as { type: 'string', minLength: 1 }. It is subsequently passed to simpleGit().clone(cloneUrl, workDir, ['--depth', '1']) without protocol validation or argument boundary separators.

⚡ Vulnerability Mechanics & Attack Flow

1. Local File Disclosure: An attacker can supply a file:/// URL (e.g. file:///etc or private server git repositories), bypassing the local directory root confinement (isWithinLocalReposRoot) that is strictly enforced on the local_path ingestion method.
2. SSRF: An attacker can point gitUrl to internal cloud metadata IP addresses (http://169.254.169.254/) or private intranet network services.
3. Git Argument Injection: If gitUrl begins with a dash (e.g. --upload-pack=... or --config core.sshCommand=...), Git interprets the URL parameter as command-line options, risking command execution.

💥 Impact Analysis

Unauthorized reading of server filesystem files, internal port scanning / metadata exfiltration, and potential remote command injection.

🛠️ Remediation & Patch

Enforce a strict whitelist regex on gitUrl requiring https:// or git@/ssh:// schemes, prohibit leading hyphens, validate hostnames against private IP/loopback ranges, and prefix the clone target with -- to prevent argument injection.

High SEC-04 Multi-Factor Authentication (MFA) Bypass via Unauthenticated 'POST /api/mfa/setup'
✓ FIXED CVSS 8.1 CWE-287 / CWE-306 ▼

Component MFA Provisioning Controller
Attack Vector Authenticated Request
CVSS v3.1 Vector CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N
📌 Vulnerability Description

In mfa-routes.ts, calling POST /api/mfa/setup provisions a new TOTP secret and executes: await db.update(users).set({ totpSecret: secret, mfaEnabledAt: null }).where(eq(users.id, req.user!.id)). Unlike POST /api/mfa/disable (which validates a current TOTP code and verifies !instanceRequiresMfa()), /mfa/setup requires neither a password nor a TOTP code, and does not check whether MFA is already enabled or mandated.

⚡ Vulnerability Mechanics & Attack Flow

If an attacker obtains temporary access to a session (e.g. via XSS or an unlocked workstation), calling POST /api/mfa/setup immediately sets mfaEnabledAt = null in the database. When the user subsequently logs in, routes.ts sees user.mfaEnabledAt == null and authenticates the user with password alone, bypassing second-factor requirements and rendering instance-mandated MFA ineffective.

💥 Impact Analysis

Second factor neutralization without knowing the existing TOTP code or password.

🛠️ Remediation & Patch

Do not nullify mfaEnabledAt in /mfa/setup. If MFA is already active, require current password and TOTP verification before allowing re-enrollment, and store the pending secret in a distinct column (or session) until activated via /mfa/enable.

High SEC-06 Sensitive Credential & Plaintext 2FA Secret Exposure in Full-Instance Backups
✓ FIXED CVSS 7.4 CWE-522 / CWE-312 ▼
Vulnerable File server/src/export/archive.ts:96-104
Component Instance Backup Archive Generator
Attack Vector Data Storage / Backup Leakage
CVSS v3.1 Vector CVSS:3.1/AV:N/AC:H/PR:H/UI:N/S:U/C:H/I:H/A:N
📌 Vulnerability Description

The full-instance backup function buildInstanceBackup() dumps the complete users table into account-dump.json inside an unencrypted ZIP archive. This dump contains Argon2 password hashes and totpSecret values stored as unencrypted Base32 strings.

💥 Impact Analysis

If a backup ZIP stored locally or in S3 object storage is accessed or leaked, an attacker gains immediate access to all users' plaintext 2FA seeds and password hashes, compromising all accounts on the instance.

🛠️ Remediation & Patch

Encrypt totp_secret at rest in PostgreSQL using AES-256-GCM (matching repository credentials), or require instance backups to be encrypted with an administrator encryption key before persisting.

callbackUrl(req) constructs the OAuth redirect_uri parameter using ${proto}://${req.headers.host}/auth/callback. When Chapters sits behind reverse proxies that forward client Host headers without normalization, an attacker can manipulate the Host header to forge redirect URIs.

Bind redirect URIs to a statically configured APP_URL environment variable rather than dynamically deriving it from incoming request headers.

📌 Vulnerability Description

The email verification endpoint POST /api/verify-email tests 6-digit numeric codes generated by generateCode() (1,000,000 possibilities, valid for 30 minutes). Unlike /login, failed attempts do not call recordFailure() in lockout.ts. Distributed callers can attempt to brute-force the verification code within the 30-minute validity window.

Medium SEC-10 Denial of Service (DoS) via Unbounded Git Ingestion & Heap Memory Exhaustion
✓ FIXED CVSS 5.3 CWE-400 / CWE-770 ▼
Vulnerable File server/src/repositories/git-sync.ts:47-51
Component Git Synchronization Scanner
CVSS v3.1 Vector CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:H
📌 Vulnerability Description

In git-sync.ts, IGNORED only excludes .git/ (unlike local-watch.ts which excludes node_modules). The sync function reads every file in the cloned repository simultaneously into memory as UTF-8 text strings: for (const path of currentPaths) files.push({ path, content: await readFile(join(workDir, path), 'utf8') }). Syncing a repository with vendored dependencies, media assets, or binary blobs exhausts Node.js heap memory and causes an out-of-memory process crash.

🛠️ Remediation & Patch

Exclude node_modules, dist, and binary extensions in git-sync.ts, and enforce a per-file size ceiling (e.g. 1MB) and binary character check before loading into memory.
