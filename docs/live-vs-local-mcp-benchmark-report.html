✅ PGVector Architectural Advantages

  • Zero IPC Overhead: BM25 text search and vector HNSW calculations run inside PostgreSQL's internal engine via C-extensions.
  • Rock-Solid Memory: Application heap fluctuated by only 3.1 MB across 800+ complex requests.
  • Operational Simplicity: 2 containers total. Zero inter-service port mapping, zero Python runtime to manage.

ℹ️ ChromaDB Operational Trade-offs

  • Microservice Serialization: Every vector query requires Node $\to$ JSON $\to$ HTTP $\to$ Python $\to$ HNSW $\to$ JSON $\to$ Node.
  • Tail Latency Spike: Under 10+ concurrent AI workers, the serialization queue inflates p95 latency to 2.6s.
  • Memory Retention: Node.js application process climbed by +152.7 MB during bulk ingestion.

🎯 5. Production Recommendations

  1. Standardize Production on mcppgvector: Matches the Ponytail principle (boring over clever, fewest containers, zero speculative abstractions). It eliminates an entire stateful Python container while delivering +23% higher throughput under AI swarm concurrency.
  2. Maintain ChromaVectorStore as an Optional Adapter: Keep the modular code in server/src/search/vector/chroma-store.ts as a pluggable driver for enterprise users who mandate external Chroma Cloud or multi-tenant Chroma clusters.
  3. Keep 120 req/min Rate Limiting: Both local and live tests proved this barrier flawlessly shields the knowledge graph from rogue AI agent infinite loops without false-positive throttling on legitimate multi-worker bursts.
