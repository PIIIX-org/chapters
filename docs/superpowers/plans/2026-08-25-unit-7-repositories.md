# Unit 7 — Repositories

Implements the unit 7 section of
`docs/superpowers/specs/2026-08-22-remaining-ui-design.md` against
`docs/superpowers/specs/2026-07-18-repository-ingestion-design.md` and
`docs/superpowers/specs/2026-07-18-code-graph-integration-design.md`.

## Locked by the two repository specs (do not relitigate)

**The viewer is read-only, permanently.** Editing code through Chapters is
listed under "explicitly out of scope" in the code-graph spec and as a hard
boundary — "not a deferred feature" — in the ingestion spec. There is no edit
path to design, no autosave, no CRDT, no trash and no revert here. A
repository's index is derived; git remains the record of truth, and every sync
hard-deletes and replaces it.

**"Open on GitHub" is git-only.** A deep link serves neither `local_path` nor
`agent_push`, which is exactly why decision 3 puts a viewer in front of all
three methods. `gitHubFileUrl()` keys off `ingestionMethod`, not off whether a
`gitUrl` happens to be set, and returns `null` for anything else — the button
is not rendered at all rather than rendered disabled.

**Symbols are not graph nodes.** The outline is per-file, on demand, next to
the code. Nothing in this unit puts a function on the canvas.

**Sharing is binary.** A repository grant has no read/edit level, because
nothing is editable; owner-only to grant or revoke. Do not copy the vault
share UI's permission selector.

**Secrets show once**, through the existing
`client/src/components/ui/SecretReveal.tsx` — the webhook secret and every
sync token, same component and same copy as MCP tokens.

## Backend additions this unit owns

### Addition 3 — repository file content

Content already lives in `repositoryFiles.content`. `GET
/repositories/:id/files` serves metadata only (`store.ts:listRepositoryFiles`
selects id/path/language/size/updatedAt), so nothing serves the text.

```
GET /repositories/:id/files/content?path=<relative path>
```

- **Auth**: session (`app.requireAuth`, already a route-level hook) plus
  `resolveRepositoryAccess` — owner *or* viewer, resolved live per request.
- **Params**: `id` — repository uuid. `path` — the full relative path,
  URL-encoded. A query param, not a wildcard segment: paths have arbitrary
  depth and a wildcard collides with `/repositories/:id/files`.
- **400** if `path` is missing or empty (JSON schema `required: ['path']`).
- **404**, identically, when the caller cannot reach the repository *and* when
  the file does not exist — a distinguishable response would let a viewer
  probe repository ids.
- **200**:

```jsonc
{
  "id": "uuid",
  "path": "server/src/app.ts",
  "language": "typescript",      // null when the extension is unrecognized
  "size": 4211,                   // bytes
  "contentHash": "sha256-hex",
  "content": "import …",
  "sourceModifiedAt": "2026-08-20T09:12:00.000Z", // nullable
  "updatedAt": "2026-08-24T11:02:11.000Z",
  "symbols": [                    // the outline; [] for unparsed languages
    { "name": "buildApp", "kind": "function", "startLine": 30, "endLine": 88 }
  ]
}
```

Implementation is two existing store functions —
`getRepositoryFile(repositoryId, path)` then `listFileSymbols(file.id)` —
which is exactly what the MCP `read_file` tool already does
(`server/src/mcp/server.ts:366`). Symbols ship *with* the content so the
outline costs no second request and can never disagree with the text beside
it.

### Addition 4 — `defaultBranch` on `repositories`

GitHub deep links need a ref and only `gitUrl` is stored.

- **Column**: `default_branch text` on `repositories`, nullable. Null for
  `local_path` and `agent_push` — they have no branch — and for a git
  repository that has not completed a first sync.
- **Migration**: `server/drizzle/0013_<name>.sql`, generated by
  `pnpm db:generate` after the schema edit so the `meta/` journal
  stays consistent. Body is one statement:
  `ALTER TABLE "repositories" ADD COLUMN "default_branch" text;` — additive
  and nullable, so it needs no backfill and cannot fail on a populated table.
- **Written by** `syncGitRepository` (`repositories/git-sync.ts`), from the
  shallow clone it already makes, in the same `db.update` that sets
  `lastSyncedAt`:
  `const branch = (await simpleGit(workDir).revparse(['--abbrev-ref', 'HEAD'])).trim()`.
  A `depth 1` clone checks out the remote's default branch, so its `HEAD` name
  *is* the answer — no extra network call, no `ls-remote`.
- **Exposed on** `repositoryView()` and on the list endpoint (see gap 1).
  Never accepted from a client: there is no branch selection in v1, per the
  ingestion spec's carried-forward assumption.
- **Client fallback**: `gitHubFileUrl` uses `defaultBranch ?? 'HEAD'`, because
  GitHub resolves `/blob/HEAD/<path>` to the default branch. A repository
  whose first sync has not landed still gets a working link instead of a
  missing button.

## Backend gaps beyond additions 3 and 4

| # | Gap | Why it blocks the unit |
|---|---|---|
| 1 | `GET /repositories` returns a trimmed shape (`permissions.ts:listAccessibleRepositories` — id, name, ownerId, mergeable, ingestionMethod, syncStatus, access) and there is no `GET /repositories/:id` at all | Sync health, "open on GitHub" and every settings field need `gitUrl`, `localPath`, `defaultBranch`, `lastSyncedAt`, `lastSyncError`, `lastWebhookAt`, `createdAt`. Fix by returning `repositoryView()` plus `access` from the list — the client then selects one out of the list (`useRepository`) and no per-id endpoint is needed |
| 2 | No way to know whether a webhook secret exists | `webhookSecretEncrypted` is correctly never served. Add a derived `webhookConfigured: boolean` to `repositoryView()`; the setup card otherwise cannot tell "not set up yet" from "set up, secret already handed over" |
| 3 | No manual re-sync, and creation triggers nothing | The ingestion spec names "manual-reindex" among the owner-only actions. A new `git` repository stays empty until the poller's next tick (minutes), and a new `local_path` repository stays empty forever (gap 4). Needs `POST /repositories/:id/sync` (owner-only, 409 if `syncStatus === 'syncing'`, fire-and-forget like the webhook handler), called on create for `git` and `local_path` |
| 4 | `startWatching` is never called | `repositories/local-watch.ts` is wired only into its own test. Nothing in `server/src` (app.ts, index.ts) starts a watcher, so **`local_path` ingestion does not work in production** — the UI would offer a method that never syncs. Needs a start-on-boot pass over local_path repositories plus a start/stop on create/delete |
| 5 | Repository shares return no grantee email | `GET /repositories/:id/shares` expands team members with emails but leaves a user share as a bare `granteeId` uuid — vault shares carry `email` (`client/src/api/shares.ts`). The roster would show a uuid |
| 6 | Sync tokens have no label | Unlike MCP connections, `repository_sync_tokens` has no `name`. A list of uuids is unmanageable once there are two agents. Optional for this unit; the list is usable ordered by `createdAt`/`lastUsedAt` |
| 7 | No file-size cap anywhere | Ingestion stores whatever it reads and addition 3 serves it. Not a blocker: the viewer refuses to render above a client-side threshold and offers the GitHub link instead. Recorded because a 40MB minified bundle in a repo would otherwise be a memory event |

Gaps 1–2 are prerequisites for the client contract below and ship with
additions 3 and 4. Gaps 3–4 are the difference between two of the three
advertised ingestion methods working and not working; **flag them to Taha in
the PR** — 4 in particular is a shipped-but-unreachable feature, not a UI
concern.

## The viewer is the existing editor, at arm's length

Decision 3 says the viewer is CodeMirror 6 with `readOnly: true` and a
different language mode. `useCodeMirrorEditor` already has the read-only
recipe (`EditorState.readOnly` + `EditorView.editable.of(false)`), but it also
hardcodes `markdown()`, wikilink decorations and wikilink autocompletion —
none of which belong in a code file — and unit 6 is rewriting that same file
for yjs.

This unit therefore adds `client/src/hooks/useCodeViewer.ts`: the same mount
recipe, no wikilinks, no autocompletion, no `onChange`, and a language
extension chosen from the file's `language`. It is ~30 lines of deliberate
duplication to keep two units out of one file; fold the two together later if
anyone cares.

Language modes cost one dependency each. Ship **`@codemirror/lang-javascript`**
only (typescript + jsx flags cover ts/tsx/js/jsx/mjs/cjs — the languages this
repo and most connected ones are written in); every other value from
`detectLanguage`, and `null`, falls back to no highlighting, which is plain
mono text and perfectly readable. `lang-python` and `lang-go` are one line
each in the map when someone connects such a repository. **Flag the new
dependency in the PR** — the design says vitest-axe is the only new one it
adds.

The hook mounts once per document, like its sibling, so the viewer is keyed on
the file path.

## Surfaces

Per the shell design there is no `/repos` index route — the spec's route table
lists only `/repos/:id/files/*`, and a repository list page would be the
dashboard-of-cards decision 1 rejected. Repositories are reached from the
scope picker and ⌘K; connecting and configuring one is a **modal stack over
any context**, the same shape unit 2 gave vault settings.

- **`/repos/:id/files/*`** — viewer route, lazy chunk (performance rule 6).
  Left: the path tree built client-side from the metadata list. Centre:
  read-only CodeMirror. Right: symbol outline. Header: repository name,
  sync-health line, "Open on GitHub" when `gitHubFileUrl` returns a string.
- **Connect modal** — three branches off `ingestionMethod`: git (URL +
  optional credential, with "stored encrypted, never shown again" stated where
  it is typed), local path (relative to the server's allowlisted root — say
  so, since a 400 otherwise reads as a bug), agent push (no fields; the sync
  token is the next step).
- **Repository settings modal** — rename, `mergeable`, "include in my merged
  graph", shares, sync tokens, webhook setup, delete.
- **Sync card** — the five `syncHealth` states, in plain language:
  never synced / syncing / failed (with `lastSyncError`) / synced but nothing
  indexed / synced, N files. For `git`, one more line: webhook delivering
  (from `lastWebhookAt`) versus polling fallback.
- **Webhook card** (git only) — `POST` returns `{ secret, webhookPath }`,
  shown once via `SecretReveal` with the path to paste beside it. Regenerating
  replaces the old secret and breaks deliveries until the host is updated: say
  that inline, before the button.

Delete copy states the actual consequence — "removes the connection and its
index from Chapters; your code is untouched" — not "this cannot be undone",
which is true of the row and misleading about the codebase.

## Client contract (written; code against it)

- `client/src/api/repositories.ts` — types, endpoints, and two pure helpers:
  `gitHubFileUrl(repo, path)` and `syncHealth(repo, fileCount?)`.
- `client/src/hooks/useRepositories.ts` — query keys and hooks.
  `useRepository(id)` selects out of the list cache rather than hitting a
  per-id endpoint that does not exist.
- `client/src/api/repositories.test.ts` — 14 tests, each mutation-verified.

`syncHealth` is where "never synced" and "synced and empty" are kept apart:
`lastSyncedAt === null` is the first, `lastSyncedAt` set with `fileCount === 0`
is the second, and an omitted `fileCount` reports `synced` rather than
guessing `empty`. Both states are reachable in normal use — a fresh connection
and a wrong path/empty branch — and they need different words and different
next actions.

## Testing

Client: vitest + happy-dom, an axe assertion per new component, **every test
mutation-verified** — break the implementation, watch that test fail, restore,
watch it pass, and record the mutation. Fixtures must vary along the axis
under test: two files, two languages, one repository with a `gitUrl` and one
without, or the test proves nothing.

`isError` is checked before `.data` is ever read, in every component here. A
repository whose fetch failed must not render as "synced, 0 files".

Server: real-database integration tests, including a viewer (not owner)
reading content, a 404 for an unreachable repository id, and `defaultBranch`
captured by a real clone in the existing git-sync test's fixture.

The client suite stubs `fetch` and cannot see a transport bug (unit 3, #110).
This unit gets a real browser pass against a running server, with a genuinely
connected repository, before it is called done.
